# Sowout

A small private panel for publishing subscription URLs. Administrators paste links generated by Rout, create users, and assign access. Users sign in and copy their links into their client. Sowout never fetches, parses, converts, or proxies those links and does not connect to Rout.

## Requirements

- Node.js 22 or newer
- An Upstash Redis database with REST access
- A Vercel project for production

## Configuration

Copy `.env.example` to `.env.local` and configure:

| Variable | Meaning |
| --- | --- |
| `UPSTASH_REDIS_REST_URL` | Upstash Redis REST URL |
| `UPSTASH_REDIS_REST_TOKEN` | Upstash Redis REST token (secret) |
| `APP_ORIGIN` | Exact public origin, e.g. `https://sowout.example.com`, with no path |

Create a Redis database in Upstash and copy its REST URL and token from its database details. Use a dedicated database: Sowout stores its state under `sowout:state:v1`. Do not commit `.env.local` or share the token. The same Redis REST interface is used locally and on Vercel. Protect Redis credentials: access to Redis gives full access to account hashes and subscription URLs.

## First administrator

Before exposing the application, run this once from a trusted local machine with the production Redis credentials in `.env.local`:

```sh
npm ci
node --env-file=.env.local scripts/init-admin.mjs
```

Enter an administrator username. A cryptographically random password is printed **once**; save it in a password manager. Initialization uses Redis `SET NX` and fails if the database is already initialized. There is no public initialization endpoint or default password. Keep a secure Redis backup: deleting the state key destroys all accounts and permits initialization again. To recover access, restore a trusted backup or reinitialize a deliberately cleared dedicated database; this deletes all existing Sowout data.

## Local development

```sh
npm ci
npm run dev
```

Open `http://localhost:3000/login`. Set `APP_ORIGIN=http://localhost:3000` for local development. The initial administrator is created by the command above, not on the website. Use a separate Redis database for development.

## Deploy to Vercel

1. Import the repository into Vercel using the Next.js framework preset.
2. Set all three variables above in the target environment. Set `APP_ORIGIN` to the exact HTTPS origin users will visit; mutations from other origins are rejected. Use separate databases and origins for preview and production. Avoid exposing uninitialized previews against production Redis.
3. Run the administrator initialization command locally against the intended database, then deploy. No resident process or cron job is required.
4. Visit `/login`, sign in, add a subscription, create a user, and grant access.

The first version targets one canonical origin per deployment. Custom domains or Vercel preview URLs require the matching `APP_ORIGIN`. HTTPS is required for secure production cookies and clipboard access.

## Security and operations

Passwords use scrypt with per-password random salts. Random session tokens are stored as SHA-256 hashes in Redis, in HttpOnly, SameSite=Strict cookies (Secure in production). Sessions expire after seven days. Password reset, account disablement, and deletion revoke existing sessions. Login attempts are limited per client IP to 10 per 15 minutes; deploy behind Vercel's trusted proxy and do not expose the application through an untrusted proxy that can forge forwarding headers. All responses are no-store. Mutation requests require the configured Origin, and admin endpoints check server-side roles.

A Rout subscription URL is a **bearer credential**. Disabling a Sowout account cannot revoke a URL already copied by a user. Rotate or revoke the original subscription in Rout when necessary. Treat links as secrets and avoid sharing screenshots or logs containing them.

The MVP stores its state as one atomic Redis document. This keeps assignments and deletion consistent but is intended for small private installations, not high-volume or multi-tenant use. Redis is the source of truth; set up appropriate backups and access controls.

## Troubleshooting

- **Unable to sign in:** verify the username and password, that the account is enabled, and that the initial administrator command completed. Login errors intentionally do not distinguish accounts. Wait 15 minutes if rate limited.
- **Invalid origin:** ensure `APP_ORIGIN` exactly matches the URL in the browser, including scheme and port, and redeploy after changing it.
- **Request failed:** check the Redis REST URL/token and Vercel function logs. Do not publish logs containing credentials.
- **Copy fails:** use HTTPS or localhost and grant clipboard permission; the link can also be selected and copied manually.
